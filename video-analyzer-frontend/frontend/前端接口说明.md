# QD-DETR 前端接口说明

本文是 `frontend` 项目与服务器模型服务之间的约定。前端不直接调用 QD-DETR Python 代码、checkpoint 或服务器文件路径，只调用下列 HTTP 接口。

当前前端开发服务器会将 `/api/*` 自动转发到 `http://localhost:8000`。部署到服务器时，可由 Nginx 或后端将前端和 API 放在同一域名下，避免跨域问题。

## 1. 接入流程

```text
选择本地视频
  -> POST /api/videos 上传文件
  -> 得到 video_id、duration、stream_url
  -> POST /api/search 提交 video_id 和英文查询
  -> 得到 moments 与 saliency_scores
  -> 前端绘制结果列表、片段标记和高光热力图
```

`video_id` 必须由后端生成并保存。前端后续查询只传 `video_id`，不要传服务器上的绝对文件路径。

## 2. 上传视频

### `POST /api/videos`

请求格式：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | File | 是 | MP4、WebM 或 MOV 文件 |
| `duration` | number | 建议 | 前端从播放器读取的秒数；后端能用 ffprobe 获取时可忽略 |

成功响应：`201 Created`

```json
{
  "video_id": "a2e4d3f1",
  "filename": "cooking.mp4",
  "duration": 150.0,
  "status": "ready",
  "stream_url": "/api/videos/a2e4d3f1/stream",
  "inference_mode": "qd-detr-clip"
}
```

字段说明：

- `video_id`：后续检索接口必须使用的唯一标识。
- `duration`：视频时长，单位为秒。
- `status`：至少支持 `processing`、`ready`、`failed`。
- `stream_url`：浏览器 `<video>` 标签使用的播放地址，应支持 HTTP Range 请求。

错误响应示例：

```json
{
  "detail": "Only MP4, WebM, and MOV video files are accepted."
}
```

## 3. 查询视频片段

### `POST /api/search`

请求头：`Content-Type: application/json`

```json
{
  "video_id": "a2e4d3f1",
  "query": "A person cuts a pizza.",
  "top_k": 3
}
```

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `video_id` | string | 必填 | 上传接口返回的标识 |
| `query` | string | 必填，建议英文 | 传入 QD-DETR 的文本查询 |
| `top_k` | integer | 1 到 5 | 返回的候选片段数量 |

成功响应：`200 OK`

```json
{
  "video_id": "a2e4d3f1",
  "query": "A person cuts a pizza.",
  "duration": 150.0,
  "moments": [
    {
      "start": 105.7932,
      "end": 120.9264,
      "score": 0.9986
    },
    {
      "start": 82.0,
      "end": 96.0,
      "score": 0.7412
    }
  ],
  "saliency_scores": [0.1523, 0.4814, 1.2031],
  "clip_duration": 2.0,
  "model_version": "qd-detr-clip-official"
}
```

前端字段使用方式：

| 字段 | 前端用途 |
| --- | --- |
| `moments[].start` / `end` | 点击结果后设置播放器时间；在时间轴上绘制检索区间 |
| `moments[].score` | 候选列表排序与“匹配度”展示 |
| `saliency_scores` | 绘制高光热力图；前端会进行 min-max 归一化，不视为百分比 |
| `clip_duration` | 高光数组每个元素所代表的秒数；官方 CLIP-only 演示通常是 `2.0` |
| `duration` | 计算时间轴位置和播放器总时长 |

约束：

- 每个 `moment` 都必须满足 `0 <= start < end <= duration`。
- `moments` 必须按 `score` 从高到低排序。
- `saliency_scores[i]` 对应区间 `[i * clip_duration, (i + 1) * clip_duration]`。
- 无结果时返回 `moments: []`，不要用 `null`。
- 查询前若视频仍在处理，返回 `409 Conflict`。

## 4. 获取视频与任务状态

### `GET /api/videos/{video_id}`

用于前端轮询上传/预处理状态。建议响应：

```json
{
  "video_id": "a2e4d3f1",
  "duration": 150.0,
  "status": "ready",
  "progress": 100,
  "stage": "ready",
  "stream_url": "/api/videos/a2e4d3f1/stream",
  "error": null
}
```

### `GET /api/videos/{video_id}/stream`

返回视频二进制内容，供浏览器直接播放。服务端应正确处理 `Range` 请求，否则视频拖动和跳转体验会较差。

## 5. QD-DETR 适配要求

服务端可使用官方 CLIP-only 演示模型：

```text
run_on_video/qd_detr_ckpt/model_best.ckpt
```

模型原始输出通常是：

```json
{
  "pred_relevant_windows": [[105.7932, 120.9264, 0.9986]],
  "pred_saliency_scores": [0.1523, 0.4814, 1.2031]
}
```

服务端只需转换为第 3 节的统一响应：

- `pred_relevant_windows` -> `moments`；每项映射为 `{start, end, score}`。
- `pred_saliency_scores` -> `saliency_scores`。
- 补充上传时记录的 `video_id`、`duration` 和固定的 `clip_duration: 2.0`。

官方模型单次输入约支持最长 150 秒视频。超过这个时长时，服务端后续可采用滑窗切分；前端不需要感知切分细节，只接收合并后的结果。

## 6. 当前前端状态

页面默认处于 Mock 演示模式；可通过“运行模式”切换至 HTTP 后端模式，按第 1 节流程上传、轮询并检索。Mock 结果不可作为模型实验结果。前端会显示接口状态、模型模式（若后端提供）、请求耗时及本页缓存命中，并校验检索响应。后端服务及真实联调仍需在部署环境验证。
